# Linux Kernel Update Automation

Automated Linux kernel updates for Amazon Linux 2023 EC2 instances using Terraform and Ansible with AWS Systems Manager (SSM) connectivity.

## Overview

This project demonstrates infrastructure-as-code for automated kernel updates with:

- **Terraform**: Infrastructure provisioning and Ansible orchestration
- **Ansible**: Kernel update configuration management via SSM
- **AWS SSM**: Secure, keyless connectivity to EC2 instances
- **Rolling Updates**: Safe, serial execution across multiple instances
- **Manual Reboot Control**: Install updates without automatic reboot

## Quick Start

### 1. Initialize Terraform

```bash
terraform init
```

### 2. Provision Infrastructure

```bash
terraform apply -var-file="dev.auto.tfvars"
```

### 3. Run Kernel Update via Terraform

**Option A: Using the wrapper script (recommended)**
```bash
./run_kernel_update.sh
```

**Option B: Direct Terraform execution**
```bash
terraform apply \
  -var-file="dev.auto.tfvars" \
  -var="run_ansible=true" \
  -var="ansible_kernel_version=latest"
```

### 4. Reboot Instance (Manual)

```bash
aws ec2 reboot-instances --instance-ids $(terraform output -raw ec2_instance_id)
```

### 5. Verify Kernel Version

```bash
./verify_kernel.sh
```

## Key Features

### Terraform Integration

- **Automatic inventory generation**: Terraform creates `ansible/inventory/hosts.yml`
- **null_resource provisioner**: Executes Ansible automatically when `run_ansible=true`
- **Variable control**: Pass kernel version and release via Terraform variables
- **State tracking**: Changes trigger Ansible re-execution

### Ansible Automation

- **SSM connectivity**: No SSH keys, uses AWS Systems Manager
- **Preflight checks**: Validates disk space, SSM agent, available updates
- **DNF update**: Installs kernel packages with retry logic
- **Verification**: Confirms packages installed successfully
- **No automatic reboot**: Manual control over instance restarts

### Safety Features

- **Rolling updates**: Serial execution (one instance at a time)
- **Fail-fast**: Stops on first error (`max_fail_percentage: 0`)
- **Check-only mode**: Dry run without making changes
- **Idempotent**: Safe to run multiple times

## Terraform Variables

### Infrastructure Variables (dev.auto.tfvars)

```hcl
region      = "us-east-1"
environment = "dev"
```

### Ansible Control Variables (ansible.auto.tfvars or CLI)

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `run_ansible` | bool | `false` | Enable Ansible execution |
| `ansible_kernel_version` | string | `"latest"` | Kernel version to install |
| `ansible_release_version` | string | `""` | AL2023 release version |
| `ansible_check_only` | bool | `false` | Dry run mode |
| `ansible_serial_batch_size` | number | `1` | Rolling update batch size |

## Reboot Process

**IMPORTANT:** This automation does NOT automatically reboot instances.

After kernel updates are installed, manually reboot to activate:

```bash
# AWS CLI
aws ec2 reboot-instances --instance-ids $(terraform output -raw ec2_instance_id)

# Via SSM
aws ssm start-session --target $(terraform output -raw ec2_instance_id)
sudo reboot

# AWS Console
EC2 → Instances → Select instance → Instance state → Reboot
```

## Workflow

1. **Terraform Apply**: Provisions EC2 instance with SSM enabled
2. **Inventory Generation**: Terraform creates `ansible/inventory/hosts.yml`
3. **Ansible Execution**: null_resource runs ansible-playbook (if `run_ansible=true`)
4. **Preflight Checks**: Validates system state, captures current kernel
5. **Kernel Installation**: DNF installs kernel packages
6. **Verification**: Confirms packages installed
7. **Manual Reboot**: Operator reboots instance when ready
8. **Post-Reboot Verification**: Run `./verify_kernel.sh` to confirm

## Troubleshooting

### Terraform Issues

**Problem:** `null_resource.ansible_kernel_update` fails

**Solution:**
```bash
# Disable Ansible in Terraform
terraform apply -var-file="dev.auto.tfvars" -var="run_ansible=false"

# Test Ansible manually
cd ansible
ansible-playbook playbooks/kernel_update.yml -i inventory/hosts.yml -e "kernel_update_check_only=true"
```

### SSM Connectivity Issues

**Problem:** Cannot connect to instance

**Solution:**
```bash
# Check instance SSM status
aws ssm describe-instance-information \
  --filters "Key=InstanceIds,Values=$(terraform output -raw ec2_instance_id)"

# Test direct connection
aws ssm start-session --target $(terraform output -raw ec2_instance_id)
```

### Ansible Collection Issues

**Problem:** `community.aws` collection not found

**Solution:**
```bash
cd ansible
ansible-galaxy collection install -r requirements.yml --force
```

## Best Practices

1. **Test in dev first**: Always validate in non-production
2. **Use check-only mode**: Dry run before actual updates
3. **Plan maintenance windows**: Schedule reboots during low-traffic periods
4. **Verify before reboot**: Run `./verify_kernel.sh` to confirm packages installed
5. **Keep old kernels**: Don't remove previous kernels immediately
6. **Monitor CloudWatch**: Enable detailed monitoring during updates
7. **Document versions**: Track which release versions are deployed
8. **Rolling updates**: For multiple instances, update serially (default)

## Scaling to Multiple Instances

To update multiple EC2 instances:

1. **Modify Terraform**: Use `count` parameter in EC2 module
2. **Update inventory logic**: Loop over instances in `main.tf` locals
3. **Set batch size**: Adjust `ansible_serial_batch_size` variable
4. **Coordinate reboots**: Use ASG or manual coordination

Example for 3 instances, updating 1 at a time:
```bash
terraform apply \
  -var-file="dev.auto.tfvars" \
  -var="instance_count=3" \
  -var="run_ansible=true" \
  -var="ansible_serial_batch_size=1"
```

## Security Considerations

- **No SSH keys**: SSM provides secure, audited access
- **Least privilege IAM**: Instance profile has minimal required permissions
- **Encrypted state**: S3 backend encryption enabled
- **VPC isolation**: Instances in public subnet with controlled egress
- **Session logging**: SSM sessions can be logged to CloudWatch
